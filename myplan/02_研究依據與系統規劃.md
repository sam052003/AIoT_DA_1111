# 02｜AirGuard AI 研究依據與系統規劃

> 文件類型：研究構想、資料／演算法規格與開發驗收計畫。以下「預計」「規劃」不代表功能已完成。

## 01｜背景與研究問題（Why）

世界衛生組織對**2021 年疾病負擔資料**的估計指出，室外空氣污染每年約造成 **420 萬人提早死亡**，與心血管疾病、中風、COPD、肺癌及急性呼吸道感染等健康問題有關。使用者提供的環境部統計指出，臺灣 **2025 年 PM2.5 年均值約 12.8 μg/m³**，相較 **2019 年 16.2 μg/m³** 有改善。以上數據正式引用時仍須核對原始公告、統計定義和來源。

**研究缺口**：濃度、顏色或 AQI 視覺化不足以直接回答「今天能不能慢跑／何時通勤／是否改走另一條路」等情境問題；模型即使 RMSE 較小，也不代表建議可靠、可解釋或能降低個人實際暴露。

**核心研究問題**：如何整合短期 PM2.5 預測、官方規則、不確定性與受約束 AI Agent，提供具可追溯證據的活動決策，並避免時序洩漏、尺度混淆與虛構建議？

## 02｜外部研究證據與適用邊界（Evidence）

| 面向 | 提供摘要中的研究主張 | 對 AirGuard AI 的啟發／限制 |
|---|---|---|
| 低交通道路改道 | 某研究報告超細懸浮微粒約 **−11%**、黑碳 **−19%**、PM2.5 **−3%** | 支持「路徑可能影響暴露」；污染物與量測情境不同，不能直接移植降幅 |
| 活躍通勤改道 | 另一研究估計約 **−15%** 暴露 | 可設定候選路線比較研究問題；需查明污染物及指標定義 |
| 替代自行車路線 | 某研究觀察 PM2.5 暴露降低 **>30%** | 說明空間與交通選擇的潛力；並非每個城市皆有此差距 |
| 倫敦通勤策略 | 選擇不同路線／交通方式的暴露降幅約 **25%–90%** | 需核對研究設計、交通方式及暴露指標，不得與本系統成果混淆 |
| PM2.5 預報決策 | 使用 **Mean Excess Exposure（MEE）** 衡量依預報決策可能承受的額外暴露 | 不只驗證預測誤差，也要考慮錯誤決策的暴露代價 |
| 可解釋性 | **SHAP** 可提供特徵貢獻的局部／整體解釋 | 可解釋模型依據，但 **SHAP 不能獨立證明因果** |

## 03｜系統功能範圍（What）

| 編號 | 功能 | 首要輸入 | 輸出／安全界線 | 優先級 |
|---|---|---|---|---|
| F01 | 官方即時空品與歷史查詢 | 監測站、時間、環境部資料 | 具來源與更新時間的官方 AQI／PM2.5 | P0 |
| F02 | PM2.5 短期預測 | 歷史濃度、氣象、時間特徵 | 1／3／6 小時 PM2.5 濃度、有效時距、不確定性 | P0 |
| F03 | 情境式活動建議 | 活動類型、時間、地點、敏感性 | 依官方指引的建議與限制聲明，不提供診斷 | P0–P1 |
| F04 | 可解釋預測與風險說明 | 模型輸出、特徵與來源 | SHAP 特徵貢獻及一般性說明；不得虛構因果 | P1 |
| F05 | 個人活動／暴露估計 | 戶外時長、活動強度、污染濃度 | 估算暴露指標、假設與不確定性；非吸入劑量實測 | P1 |
| F06 | 候選路線比較 | 起訖點、交通方式、出發時刻、路網與污染時空資料 | 可比路線的**估計**暴露、熱點、替代建議；須先做尺度驗證 | P2 |
| F07 | 安全降級 | 缺值、測站歧義、過期資料、越界時間、工具異常 | 明確表示無法提供可靠數值，改用可核查的官方資訊 | P0 |

**核心設計原則**：先完成測站尺度的「預測＋規則＋可追溯 Agent」，再進入需要更多資料的路線級推估。**路線級空品決策導航**是研究擴充目標，不能因有測站 PM2.5 模型，就推定具備道路污染熱點辨識能力。

## 04｜八模組架構（How）

```text
① User / Web UI
        ↓
② Query Interpreter          ← 地點／時間／活動／敏感族群意圖解析
        ↓
③ Planner Agent              ← ReAct + Tool Allowlist + 安全規則
        ↓
④ Data Acquisition           ← 官方 AQI、PM2.5 歷史、氣象、可選路網資料
        ↓
⑤ Analytics Engine           ← 資料品質檢查 + 預測 + 不確定性 + 暴露估計
        ↓
⑥ Domain Rules               ← 官方活動指引、時效／尺度／族群限制
        ↓
⑦ Decision Engine            ← 解釋、來源核對、比較、降級策略
        ↓
⑧ Output & Interaction       ← 建議＋依據＋模型／官方身分＋更新時間
```

流程守門條件：

1. **資料守門**：檢查來源、測站、位置、時戳、平均時間窗、缺值、資料延遲與單位。
2. **預測守門**：只在支援時距內使用模型，並標明 PM2.5 非官方 AQI。
3. **規則守門**：官方活動指引優先；Agent 僅做情境解析與工具調度，數值由可審計工具計算。
4. **安全降級**：資料無法可信辨識時回報未知與最新可用官方資訊，不以 LLM 補造數值。

## 05｜資料與路線尺度（Data Contract）

- **資料類型**：環境部官方即時 AQI 與測站 PM2.5、逐時歷史數據、環境部空品預報、中央氣象相關資料、測站座標與時間資訊。資料集代碼與版本應在實作時重新核對 API 文件。
- **模型資料契約**：
  - `station_id`、`observed_at`（含時區）、`fetched_at`、`source_id`、`pollutant`、`unit`、`averaging_window`、`quality_flag`；
  - `forecast_issued_at`、`forecast_target_at`、`horizon_hours`、`model_version`、`predicted_pm25`、`uncertainty`；
  - 不允許把預測時刻之後才可獲知的欄位當成特徵。
- **路線功能新增需求（P2）**：路網圖、路段幾何、行程時間、道路／交通強度或移動監測資料，以及有足夠時空解析度的污染推估方法。若無這些證據，只能顯示「近測站資訊與一般性防護建議」，**不能排序哪條街道較乾淨**。
- **暴露估計邊界**：需說明積分時間、濃度估計、呼吸／活動強度假設；「暴露」不等於實際吸入劑量，不等於醫療風險診斷。

## 06｜Track A：預測模型與評估（ML）

### 06.1 預測任務與候選方法

- 目標：測站尺度 **1／3／6 小時** PM2.5 濃度。
- Baseline：**Persistence**（延用最近觀測值）、**Seasonal Naive**。
- 比較模型：**Ridge、Random Forest、XGBoost**。
- 候選特徵：PM2.5 歷史滯後值與滾動統計、時間週期、可取得的氣象與測站特徵。只使用在預測發出當下已可取得的值。

### 06.2 防時序洩漏與回測

1. 依時間排序；先切分訓練／驗證／測試（**70／15／15** 為提案設定），保留時間順序。
2. 以 **Rolling-origin／前向回測** 進行模型選擇；特徵工程、補值、標準化與超參數調整均限制在當期訓練資訊內。
3. 每個預測時距分別報告 **MAE、RMSE、Skill Score**；Skill Score 的參考基準與數學定義需固定、公開。
4. 報告測站、季節、污染高峰及資料缺失情境的分層結果；若模型未優於 Persistence，**如實報告負結果**，保留基線或退化為趨勢資訊。
5. 可選：預測區間覆蓋率／校準與 SHAP 解釋，不將關聯誤解為因果。

> 不應預先宣稱 XGBoost 最佳或系統已準確預測；需以固定測試集的實際結果決定。

## 07｜Track B：Agent 決策、規則與路線驗證

**至少 30 個固定驗收案例**；建議按 **6 類 × 每類 5 例** 編列測試資料：

| 類別 | 案例焦點 | 必查項目 |
|---|---|---|
| B01 | 正常慢跑／通勤／活動時段 | 工具選擇、時間理解、來源、建議可執行性 |
| B02 | 測站／地名歧義 | 是否追問或清楚揭露位置假設、不捏造來源 |
| B03 | API 中斷、舊資料、缺值 | 安全降級、資料時間戳、未提供無根據數字 |
| B04 | 超出 1／3／6 小時預測時距 | 拒絕不支援的精確預測、提供替代說明 |
| B05 | 官方 AQI 與模型 PM2.5 混淆 | 雙軌資訊分流、單位／平均窗一致性 |
| B06 | 敏感族群、路線與暴露風險 | 官方規則優先、不做醫療診斷；路線缺資料不得編造排序 |

**Agent 指標**：工具選擇正確率、來源完整率、規則一致率、安全降級成功率。必要時另量測時間／空間解析正確性與建議理由可追溯性。

**路線級新增評估（功能上線前必做）**：

- 在相同 OD（起終點）、交通方式與出發時間下，記錄候選路線行程時間、空間覆蓋率、推估濃度／暴露與不確定性。
- 用獨立路段／移動量測或適當的外部資料檢驗路段污染排序；沒有獨立驗證就不把路線排序視為可靠功能。
- 比較「最短時間路線」「低暴露路線」「不改道、調整出發時間」的成本取捨。
- 以 MEE 或明確定義的暴露損失評估決策品質；**不可把文獻中的 3%／11%／15%／30%／90% 當成系統保證**。

## 08｜六週開發里程碑（Roadmap）

| 週次 | 主要工作 | 具體驗收物 |
|---|---|---|
| W1 | 資料盤點、官方來源與欄位契約 | 資料字典、品質檢查、API／CSV 樣本 |
| W2 | 時序特徵、Baseline 與回測 | 可重現切分、Persistence／Seasonal Naive 指標 |
| W3 | Ridge／RF／XGBoost、Agent 白名單 | 模型訓練管線、受控工具、來源／守門規則 |
| W4 | Web UI、決策引擎、可解釋說明 | 官方 AQI／預測分流、情境輸入、降級畫面 |
| W5 | Track A／B 雙軌驗證、消融與風險測試 | MAE／RMSE／Skill、≥30 測試案例的可重現結果 |
| W6 | 文件、Demo、口頭答辯與成果交接 | README、系統架構、實驗報告、限制說明 |

**延伸 P1／P2**：個人暴露預算與路線級導航在核心研究穩定後啟動，資料充分時另排時程，不混入 W1–W6 的已承諾成果。

## 09｜風險管理（Risks）

| 風險 | 緩解策略 |
|---|---|
| 官方 API 延遲、缺值與測站變更 | 快取與時效標示、資料品質檢查、降級提示 |
| 模型落後於 Persistence | 報告負結果，採用更穩健基線或僅顯示官方趨勢 |
| Agent 編造數字或醫療結論 | 工具白名單、來源核對、官方規則守門、審計日誌 |
| AQI 與 PM2.5／平均窗混淆 | 在 UI、API 和說明文字中嚴格分流 |
| 測站尺度不足以支撐路線比較 | P2 先做資料可行性與空間效度驗證，未通過則不發布路線排序 |
| 特徵洩漏、預報評估不公 | 嚴格時間切分、時點可用性檢核、可重現回測 |
| 不完整引用或誇大成效 | 逐項補全 DOI／來源、對照研究條件、區分預期與已證實結果 |

## 10｜預期貢獻與報告呈現（Expected Outcomes）

1. **方法貢獻**：可重現的短期 PM2.5 時序驗證與基線比較。
2. **系統貢獻**：有來源與安全界線的 AI Agent 決策支援鏈。
3. **決策貢獻**：在可靠資料範圍內，讓使用者理解時段、活動與防護選項。
4. **延伸貢獻**：建立暴露估計與路線級分析的資料要求及驗證方法，作為後續智慧城市空氣健康研究方向。
